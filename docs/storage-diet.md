# Как база не забивается (бесплатный Supabase: 500 МБ)

## Что делает проект

| Что | Где | Эффект |
|---|---|---|
| Ежедневная чистка | `supabase/18_storage_diet.sql` + `.github/workflows/daily-cleanup.yml` | удаляет старые объявления, стирает тяжёлый `raw_text`, обрезает `price_history` |
| Агентским `raw_text` не пишется вообще | `scraper/src/run.js` | самое тяжёлое поле не растёт на объявлениях, которые мы не показываем |
| `raw_text` режется до 3000 символов | `scraper/src/run.js` | |
| История цен — не больше 30 записей | `scraper/src/listingScoring.js` | |
| Один запрос на пачку вместо запроса на каждое объявление | `getListingsLiteByIds` в `scraper/src/db.js` | меньше запросов и трафика |
| Темы Telegram читаются один раз за прогон | `getTopicId` в `scraper/src/db.js` | |
| Ночью скрапер запускается реже | `.github/workflows/scrape.yml` | меньше запросов ночью |
| Размер базы + алерт в Telegram | `.github/scripts/daily-cleanup.mjs` | предупреждение при ≥ 350 МБ |
| Убран расчёт «выгодных» | удалены `marketStats.js`, `dealScoring.js` и др. | исчез тяжёлый запрос на 45 дней данных |

## Включение (по порядку)

1. Supabase → SQL Editor → выполнить `supabase/18_storage_diet.sql`.
2. GitHub → репозиторий → Settings → Secrets and variables → Actions. Нужны секреты `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID` (для алертов).
3. Запустить вручную Actions → Daily cleanup → Run workflow. Он работает в **пробном режиме**: в логе будет `would_slim / would_trim / would_purge` — сколько строк затронет чистка. Ничего не удаляется.
4. Если цифры разумные — в Variables создать `DAILY_CLEANUP_LIVE` = `true`. С этого момента чистка идёт каждую ночь (~02:41 по Ташкенту).

## Настройки (необязательные переменные в GitHub Variables)

- `KEEP_DAYS` (14) — сколько дней хранить обычные объявления.
- `KEEP_AGENT_DAYS` (30) — агентские хранятся дольше: они маленькие, а их телефоны нужны, чтобы замечать номер, который висит на нескольких объявлениях.
- `TEXT_DAYS` (7) — через сколько дней стирать полный текст у обычных объявлений. После этого на сайте у старого объявления нет описания, а поиск по тексту его не найдёт.
- `DB_SIZE_ALERT_MB` (350) — порог предупреждения.
- `NIGHT_INTERVAL_MIN` (60), `NIGHT_START_HOUR` (0), `NIGHT_END_HOUR` (7) — ночной режим скрапера по времени Ташкента. `NIGHT_INTERVAL_MIN=15` выключает его.

## Что чистка НЕ удаляет

Объявления, с которыми команда уже работала: «Связался», «Беру в работу», есть заметка или пометка «агент».

## Заметки

- Автоочистка не требует свежего бэкапа. Если нужна страховка — рядом уже есть `supabase-backup.yml` (раз в неделю).
- После первой большой чистки размер файла базы может не упасть сразу: Postgres переиспользует освобождённое место. Если нужно вернуть место системе — `vacuum full public.listings;` (кратко блокирует таблицу; если SQL Editor не даёт выполнить, то через `psql`).
- Частоту запусков скрапера (раз в 15 минут) задаёт внешний cron-job.org — в репозитории её изменить нельзя.
